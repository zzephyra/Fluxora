# ADR-010: 首期不做计费账本

## Status

Accepted

## Context

视频和模型调用有真实成本。完整的 Credits、预留、结算和退款需要账本、幂等扣费和失败补偿。首期产品目标是走通生成链路，而不是支付系统。

## Decision

首期不实现订单、支付、Credits、Quota 账本，也不根据前端或 Elasticsearch 计算费用。

`generation_attempts` 可以记录供应商、模型、用量和观察到的成本，仅供诊断。这些字段不是余额。

启用计费前必须新写 ADR。届时账本只放在 PostgreSQL，预留和结算与创建任务处在明确的事务边界内，并以业务幂等键防止重复扣费。模型不得绕过额度检查创建付费生成。

## Alternatives

- 首期同时实现 Credits 预留和结算。
- 用 Elasticsearch 聚合或前端估价作为余额。
- 在供应商控制台人工对账，应用内不留用量。

## Trade-offs

没有账本就不能在产品内阻止超支。保留用量字段可以让以后的账本有诊断数据，但不构成扣费。现在做完整账本会把第一阶段的状态机和失败补偿扩大一倍。

## Consequences

当前生成接口不接收价格参数，也不返回余额。任何“先扣费再生成”的需求都视为架构变更，而不是普通功能。

## Migration

项目尚未实现。启用计费时从零增加账本表，不把历史诊断字段直接当成已结算金额。
