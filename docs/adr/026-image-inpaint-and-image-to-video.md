# ADR-026: 图片局部重绘与图生视频

## Status

Accepted — 2026-09-29。用户确认实施本提案。

模型分配部分已由 [ADR-027](027-unified-media-models.md) 取代：局部重绘复用统一图片生成模型，图生视频复用统一视频生成模型。

## Context

图片编辑器已有画笔、蒙版、撤销与提示词，但 `requestInpaint` 仅返回 501，生成视频按钮禁用。[ADR-020](020-text-to-video.md) 明确只开放文生视频且禁止参考图输入；现有模型能力没有局部重绘。因此本次需要扩展 Gateway 能力、生成输入契约和编辑器交互。

## Decision

### 用户流程

- 局部重绘：选取图片 → 涂抹区域 → 输入修改描述 → 明确提交 → 展示真实任务状态 → 查看新图片。原图保留，新结果进入同项目资产与生成历史，允许继续编辑。
- 生成视频：点击图片上的生成视频 → 展示首帧预览、运动描述及模型支持的参数 → 明确提交 → 在现有视频结果区查看任务和成片。打开弹窗本身不创建任务。
- 使用编辑器当前画布的导出图片；裁剪、旋转等本地修改应与提交的图片、蒙版保持一致。未经修改的图片可直接引用已有项目资产。
- 没有配置匹配模型时显示可理解的不可用原因。不给出虚假成功或模拟进度。扩图、智能消除不属于本次新增能力。

### 模型与任务

- 增加独立 `image_inpaint` 模型能力与管理员指定入口，启用已有 `image_to_video` 能力调用；不回退到文生图或文生视频冒充完成。
- 复用现有 generation_tasks、GenerationOutput、图片/视频 Worker、查询与取消接口。区分不可变操作类型和能力快照，旧任务默认保持现有行为。
- 图片重绘沿用图片状态机；图生视频沿用 ADR-020 的 submitting、远端任务 ID、轮询与提交结果不明的恢复规则，不自动重复付费提交。
- 首期沿用现有供应商体系：为图片适配器增加真实蒙版编辑接口，为 DashScope 视频适配器增加单首帧图生视频。实现前根据官方协议确认受支持模型及输入限制；普通 OpenAI 兼容文生图接口不能被默认视为支持蒙版编辑。
- 前端只能选择服务端公开的有效参数，不能传入模型配置 ID、供应商地址或密钥。未适配的模型/参数在提交前明确拒绝。

### 输入与持久化

- 扩展项目内输入保存契约，保存当前画布及重绘蒙版的不可变私有对象；元数据、归属与状态先登记 PostgreSQL，字节经现有 Storage Gateway 写入，只有 ready 输入可被任务引用。
- 原图、画布与蒙版引用必须属于已授权项目。用户级 UploadFile 不能直接冒充项目 Asset；本次不扩大为任意 URL 或跨项目素材输入。
- 图片与蒙版必须由后端解码验证格式、字节数、像素上限和相同尺寸；拒绝空蒙版。统一蒙版语义为白色编辑、黑色保留，橡皮恢复黑色；适配器负责转换为供应商所需透明通道语义。
- 输入对象不作为生成结果缩略图展示；任务记录输入引用、摘要、操作、提示词与参数快照。幂等摘要包含输入内容，网络重试复用幂等键。
- 上传中断、数据库提交失败与未使用输入需有回收策略，不能删除活动任务仍引用的对象。供应商请求不放在数据库事务内。
- 供应商获取图片由服务端按适配器协议处理，优先传递受限图片字节；必须使用 URL 时仅生成有限时效的私有对象访问地址，不持久化签名 URL，不接受任意外部 URL。

## 验收

- 两个入口完成提交、状态查询、失败反馈、成功结果预览和资产入库；刷新后能在生成历史恢复查看任务。
- 验证跨项目引用拒绝、成员权限、CSRF、无效/超大图片、尺寸不匹配、空蒙版、未配置模型、重复提交与供应商错误。
- 验证画笔/橡皮及裁剪后图像和蒙版坐标一致，切换图片或项目时旧异步响应不会覆盖新界面。
- 验证图生视频提交不明不重发、排队取消与现有文生图/文生视频兼容。
- 同步迁移（如需）、OpenAPI、生成类型与相关规范，执行后端测试、前端交互测试、类型检查与构建。
- 替身测试不能替代真实供应商验收；真实调用需要已配置并支持对应能力的模型及凭据，最终交付明确说明是否完成真实调用。

## Consequences

已获确认，修订 ARCHITECTURE.md 与 API/数据/运行规范，ADR-020 中只允许文生视频和禁止参考图的条款由本 ADR 在单首帧图生视频范围内替代。不引入新队列、状态枚举、计费或独立生成系统。

图片输入校验采用 Pillow：现有标准库与依赖不提供 PNG/JPEG/WebP 完整解码、像素限制和蒙版通道转换。
