# ADR-021: 登录后进入个人创作空间

## Status

Accepted — 2026-09-27。用户要求把“先创建项目，再进入创作”改为“登录后直接创作，按需使用创作空间”。

## Context

Project 是权限、资料、记忆和生成记录的隔离边界。前台把进入工作台放在项目列表之后，用户必须先建项目。已有项目、成员和资源不能被静默合并。

对话、RAG、记忆和通用资产库仍未实现。这次只调整进入方式和默认空间，不补做这些系统。

## Decision

- 底层继续使用 Project 与 `project_id`。前台称“创作空间”。不另建 Workspace 业务模块，也不做全仓库重命名。
- 每个用户至多一个未删除的个人空间，`kind=personal`，名称为“个人空间”。数据库用部分唯一索引 `UNIQUE(created_by) WHERE kind='personal' AND deleted_at IS NULL` 保证并发下不会建出两个。
- `POST /api/v1/projects/personal` 获取或创建该空间。不能用项目列表的第一项代替。已有标准空间保持原样，不搬迁数据。
- 个人空间被所有者删除后，索引不再占用；下次获取会新建一个空的个人空间。旧空间及其资源保持已删除，不恢复、不合并。所有者不能退出自己的个人空间，因此登录入口不会因为退出成员关系而消失。
- 登录成功进入 `/studio`，由上述接口打开个人空间，再进入既有 `/projects/:projectId` 工作台。深链接仍使用原路由。失效的项目地址回到 `/studio`，重新获取个人空间，不用假项目。
- 普通创作和生成使用当前空间，不必先选择空间。新建的是 `kind=standard` 的创作空间。
- 新建对话不等于新建空间。项目隔离只是访问上限。一次模型调用只使用当前对话，以及用户明确选择或已确认启用的资料、设定和记忆。空间内的历史对话、资料和记忆不会默认全部进入上下文。这些调用尚未实现。
- 资产仍归属各自的 `project_id`。全部作品只是当前用户有权访问空间的汇总视图，由服务端确定范围。该列表尚未实现；资产页保持未接入，不返回虚构作品，也不因此开放跨空间检索或记忆。

## Consequences

登录不再停在项目列表。`/projects` 成为管理创作空间的入口。切换空间时卸载当前工作台，从而清掉本地草稿并取消进行中的请求。对话、RAG、记忆和跨空间资产列表仍未实现。
